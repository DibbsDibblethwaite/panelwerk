# Second review, 2026-11-22: Panelwerk

`~/code/panelwerk` on `main` at `5694d7e` (2026-11-14, "CHANGELOG: v0.4.0's agreement line reads properly"; tag `v0.4.0` is the newest). Read-only: nothing built, nothing run, no file changed. "Verified" means I read the lines cited; a finding I could not settle by reading is marked "unverified". Sizes are human developer-days.

Read: `CLAUDE.md`, `README.md`, `CHANGELOG.md`, `docs/proposal.md`, every source file in the three crates, every test file, the hooks, `coverage.sh`, `consumers.sh` and the header of `comment-drift.sh`. To check the tagging practice against reality I also read each consumer's Panelwerk lines in its `Cargo.toml`, the start of Kör's, Fläns's and Rödalog's hooks, and compared Kör's and Fläns's `app.rs` with `diff`. I did not review the plugins.

## Summary

**What is sound.**

- The layering holds. `panelwerk-text` has no dependencies, and `panelwerk-panel` has only `egui =0.37.0` and `serde_json`. Neither names nice-plug. Each crate's `tests/manifest.rs` checks this. There is `#![forbid(unsafe_code)]` and `#![deny(missing_docs)]` in all three crates.
- Nothing can reach the audio thread. The value functions allocate a `String` and say so. The settings file is read and written only from GUI code.
- `hold::Held` is careful. It never calls the host with its `RefCell` borrowed (`begin`, `frame`, `close`), and a test proves it (`pw_hold_a_shows_that_calls_back_into_the_held_edits_is_safe`). The batch logic, the limit, a clock that goes backwards and nested begins are all covered. The 48-case grid (3 hosts × 4 gesture paths × 3 cadences) tests the fault and the cure separately.
- The value text is right at its edges: half away from zero, no negative zero, the format chosen by the value as rounded. Each form reads back to the same text.
- The palette's comment is true. I recomputed all 11 `TEXT_ON` pairs. The closest is `DIMMED_TEXT` on `HOVER` at 4.739:1, as the test's comment says.
- The tests touch no real user folder. The settings tests write under `CARGO_TARGET_TMPDIR`, and `settings::file_in` takes `%APPDATA%` as an argument. No test sleeps. The test kit's clock is simulated, at 0.1 s a pass. No test is ignored.

**The three things that matter most.**

1. **Klinga depends on Panelwerk, but Panelwerk doesn't know it (W-1).** Klinga pins `panelwerk-text v0.4.0`. It is not in `consumers.sh`, not in `--pins`, and not in the docs' "three consumers". So a tag can be cut without Klinga's check, and a family update can leave it behind. Klinga's panel, still empty, is the next to adopt the panel layer.
2. **The hardest part of held edits lives outside the library, in copies (W-2).** This is the part that is safe only under nice-plug's VST3 and CLAP wrappers: `shows` comparing plain values, `Mutex<Held>`, and `take_open` handed to a `BackgroundTask` from a joined thread. Panelwerk gives it as prose. Kör and Fläns carry near-identical ~320-line `app.rs` adapters. Rödalog keeps a third, private port of the whole mechanism. The rules that make it safe are tested in no shared place: the VST3 `removed()` re-borrow abort, and the `track_info_updated` deadlock.
3. **A host gesture can be left open, and the API doesn't stop it (W-3).** Held edits end only in `Held::frame`. A consumer that forgets to call it, or ignores its `true`, leaves the host's gesture open. Without held edits, a knob whose drag ends while it isn't drawn never sends its `end`. `frame` is not `#[must_use]`, and nothing checks it in debug builds.

Counts: 0 high, 3 medium, 9 low.

### W-2 · medium · The nice-plug side of held edits is prose plus copies, untested in Panelwerk

**Where:** `crates/panelwerk-panel/src/hold.rs:60-114` (the module doc, "Wiring it in") and `CHANGELOG.md` v0.4.0 (the same text). The copies: `~/code/koer/crates/koer-plugin/src/app.rs` (323 lines) and `~/code/flaens/crates/flaens-plugin/src/app.rs` (321 lines). A `diff` of their adapters shows only names, comments, Kör's `text` and its `unsupported` field differing. Each has its own `shows` override and `self.held.lock()…take_open()` at line 235-236. Rödalog keeps its own port of the mechanism (`roedalog-plugin/src/preset.rs:501-556`, `window.rs:312`), as the CHANGELOG says.

**What:** the library's part (`Held`) is small and well tested. The part that crashes or deadlocks a host if done wrong is a recipe in a doc comment. That part is: never end an edit inside `IPlugView::removed` or `gui.destroy`; hand the edits to a task queued to the main thread from a thread of its own; don't let `endEdit` reach `track_info_updated` while the app's lock is held; override `shows` with plain values. Each consumer writes it out again, and each tests it on its own.

**Why it matters:** this is the code found by crashes in Cubase (CUBASE-1b). Three copies, with Klinga a fourth, will drift. A fix found in one won't reach the others unless someone remembers to carry it, which is the "Cubase fixes for the family" chore. Panelwerk can't hold the code as it stands, because it must never depend on nice-plug (each consumer vendors and patches its own).

**Suggested:** ask Ian to choose one of these.

- (a) A fourth crate, `panelwerk-nice`, depending on `nice-plug` by the same git source each consumer already redirects to its vendored copy with `[patch]`. It would hold the `ParamHost` adapter over `ParamPtr`, `shows`, and the close-time hand-off. Its tests would run against Rödalog's VST3 host stand-in, moved here.
- (b) Keep the copies, but move one "reference adapter" into the test kit's docs as a compiled doctest against a minimal trait, so the recipe at least compiles.

Rödalog's port should go when it adopts the panel at P (PW-10), not later. **Size:** (a) 1.5–2 days, (b) 0.5 day. Before Klinga's panel at the latest.

**Verified** by reading: that the copies exist and match. **Unverified:** whether (a) resolves cleanly under every consumer's `[patch]`.

### W-3 · medium · A host gesture can be left open, and the API doesn't guard against it

**Where:** `crates/panelwerk-panel/src/hold.rs:271` (`pub fn frame`, not `#[must_use]`); `src/gesture.rs:38-66` (`knob`: `begin` at `drag_started`, `end` only at `response.drag_stopped()`).

**What:** there are two ways this can happen.

- **With held edits wired in:** every end reaches the host only from `frame`. A consumer that doesn't call `frame` each pass never ends anything until `close` or `take_open`. A consumer that ignores `frame`'s `true` (no `request_repaint`) ends edits only at the next input. That could be minutes in a host that draws only on demand. Rödalog v3 "needed exactly this" (CHANGELOG). The compiler would warn about an ignored `true` if `frame` were `#[must_use]`.
- **Without held edits:** `gesture::knob` sends `end` only if the same response reports `drag_stopped`. If the control isn't drawn in the pass where the button is released, no response is made for it, and the host's gesture stays open. That happens when a preset, automation or a mode change hides it mid-drag, or when the window closes mid-drag.

**Why it matters:** an open gesture keeps a host in touch or latch on that parameter. In Cubase, automation is written until something ends it. It is silent: no test in a consumer would catch a missing `frame` unless it models a host.

**Suggested:**

- Mark `Held::frame` `#[must_use = "ask for another frame while an edit waits"]`.
- Add a `debug_assert!` in `Held::end` that `frame` has run at least once (`now` is still 0.0 otherwise).
- In `gesture::knob`'s doc, say that a control must be drawn until its drag ends, or the consumer must end it itself.

A minor-version API change under rule 2 (the attribute alone changes nothing a consumer shows). **Size:** 0.5 day with tests.

**Verified** by reading Panelwerk. **Unverified:** that egui 0.37 sends no `drag_stopped` for a widget not interacted with in the release pass. I read egui's behaviour from its design, not its source.

### W-6 · low · Bad zoom ranges panic on the GUI thread

**Where:** `crates/panelwerk-panel/src/zoom.rs:151` (`range.menu.len() - 1`); `zoom.rs:51` (`f32::clamp(self.min, self.max)`).

**What:** an empty `menu` underflows: it panics in debug, and in release it makes a huge rectangle. `min > max`, or a NaN bound, panics inside `clamp`, and every zoom path calls `clamp`: `choose`, `follow`, `settings::read`/`write`/`opening_zoom`. A panic on the GUI thread inside a plugin takes the host down.

**Why it matters:** each `Range` is the consumer's `const`, so the risk is a typo, but the failure is a host crash. The API doesn't document the precondition.

**Suggested:** document "`min <= max`, both finite; `menu` not empty, smallest first". Add `Range::new` as a `const fn` that asserts these, so a bad constant fails to compile, and have `menu` return early on an empty slice. **Size:** 0.25 day.

**Verified** by reading.

### W-7 · low · `consumers.sh` runs each consumer's hook with nothing staged, so staged-file steps don't run

**Where:** `scripts/consumers.sh:188` (the clone's `Cargo.lock` re-resolved, left unstaged) and `:200` (the hook run). Against `~/code/koer/scripts/hooks/pre-commit:27` and `~/code/flaens/scripts/hooks/pre-commit:27`, which run the licence check only when `Cargo.lock` or the licence files are staged. Rödalog's hook decides what to skip and record from the staged inputs (`scripts/hooks/pre-commit:40`, `:177-201`).

**What:** in the clone, the only change is the unstaged `Cargo.lock`. Kör's and Fläns's licence checks therefore never run in the consumer check. Rödalog's skip logic hashes an index equal to HEAD.

**Why it matters:** a Panelwerk change that alters a notice or a dependency licence passes the consumer check, and is found only at the family update. That is a step later than rule 14 means.

**Suggested:** `git -C "$clone" add Cargo.lock` before running the hook (the clone is reset at the next run anyway), and pass `ROEDALOG_HOOK_FULL=1` in Rödalog's entry. **Size:** 0.25 day.

**Verified** by reading for Kör and Fläns. **Unverified** for what Rödalog's skip decides in this case.

### W-8 · low · `--pins` passes when it can read no pin at all

**Where:** `scripts/consumers.sh:143-151`.

**What:** a pin that the one regex can't read is reported as "nothing" and stored as `none`. That includes a `rev =`, a `.git` suffix on the URL, or a table over several lines. If every consumer reads as `none`, the set has one member, and the script says "every pin the same" and exits 0.

**Suggested:** fail on any `none`, and name the consumer. **Size:** 0.1 day.

### W-10 · low · The settings file's temporary name is shared by every instance

**Where:** `crates/panelwerk-panel/src/settings.rs:44` (`path.with_extension("json.tmp")`).

**What:** two instances writing at the same moment write the same `panel.json.tmp`. One rename can then fail, or carry the other's zoom. This is harmless if every host closes windows one at a time on its main thread, which I believe Reaper and Cubase do.

**Suggested:** a name with the process ID and an address-derived number (`panel.json.<pid>-<n>.tmp`), or accept it in a comment. **Size:** 0.1 day.

**Unverified:** I did not confirm that the hosts close windows serially.

### W-12 · low · The zoom's host model is egui-baseview's, and the docs don't say what a VST3 host such as Cubase needs

**Where:** `crates/panelwerk-panel/src/zoom.rs:5-12` (how the window follows); `tests/zoom.rs:69-99` (`host_resizes`, a model of egui-baseview).

**What:** the module doc and the tests describe only egui-baseview's behaviour. Rödalog needed three framework patches before its panel's size worked in Cubase LE 16 under VST3:

- patch 10, the resize request reaching the host;
- patch 12, the host's scale factor taken before `attached`;
- patch 13, `WM_PAINT` leaving the window valid.

These are in `vendor/PATCHES.md:254-397`. Panelwerk's zoom is shared by Kör and Fläns, and Klinga will share it.

**Why it matters:** a consumer could adopt `zoom::follow`, pass every Panelwerk test, and still resize wrongly in Cubase.

**Suggested:** one paragraph in `zoom`'s module doc naming the framework patches a VST3 consumer needs, and pointing at Rödalog's `vendor/PATCHES.md` and the family Cubase plan. **Size:** 0.1 day.

**Unverified:** whether Kör's and Fläns's vendored nice-plug already carry patches 10 and 12. I did not read their `vendor/`.
